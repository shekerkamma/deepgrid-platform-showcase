01 — THE PROBLEM

Hungry compute, narrow pipe

The DP engine fetches one descriptor at a time, generates one address per cycle. 8 PCOREs queue for one engine. When PCORE 0 is loading, PCORE 1 through 7 wait. ~35 cycles of fixed setup × 8 turns = serial overhead.

02 — THE FIX

Eight kitchens, one pantry

Each PCORE gets its own small DMA — 16-entry descriptor table, 3-level address generator, FIFO. They all pull from a shared SRAM L2 in parallel. SRAM banks become the bottleneck instead of dispatch. Bandwidth scales 4-8×.

03 — THE COST

Architecture, not magic

Each LDMA ~600 LUT × 8 = 4,800 LUT extra. Plus arbitration logic, plus firmware compiler changes. 16-24 weeks of focused RTL work — too much for SoC1.2, right-sized for SoC1.3 hybrid or SoC2 (28nm ASIC).

Bottom line
YOLO frame: 470 ms today → ~85 ms with per-PCORE DMA.
Same silicon process, same MAC count. Just stop making compute wait for data. The architectural ceiling lifts from 2 fps to 12 fps — without adding a single multiplier.
